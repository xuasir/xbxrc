## Background / Goal

按[已确认方案](../isu/2026-11-11-pc-development-production-diagnostics.md)及用户补充落实：构建确定开发 / 生产模式；请求失败直接导出对应问题；用户主动采集可后台持续；自动异常与手动采集均形成历史记录，忘记或取消导出后可回溯。生产默认常规后台记录，稳定运行时可切轻量。

## Scope / Contracts

1. 复用 `runtime_trace` writer、schema v3、RPC、原生文件对话框和几何导航；Rust 持有采集期限、问题关联、上下文缓冲、导出截止点与文件写入。
2. 高级诊断采用精简布局：生产首行切换常规 / 轻量，随后为采集 / 导出操作与紧凑历史列表；开发端显示有效模式与折叠工具。旧 debug / 手动 profile 从产品入口移除，兼容字段按构建默认归一化。开发启动支持 `XBX_TRACE_MODE=production` 进行生产成本复验。
3. 生产常规默认每 5 秒保留一次健康 / 输入周期摘要，轻量每 30 秒一次；关键事件持续保留。最近 10 秒安全周期摘要进入 96 行 / 256 KiB 有界缓冲，包含已采样写盘的行。RPC 失败与媒体 / 输入异常保留可用前文并开启后 10 秒详细窗口；同类故障在首次发生后 30 秒内合并计数，窗口最长到首次异常后 40 秒。自动详细采集每分钟最多三段，writer 同时最多八个活动记录窗口。主动采集最长 10 分钟，Rust 使用单调时钟管理期限。
4. RPC 错误携带本地问题引用；通用错误组件、登录、列表、设置 / 更新及串流入口使用统一导出动作。安全记录包含操作类别、开始时间、耗时、错误码及安全错误分类；协议流程的详细阶段复用现有 trace。
5. 自动异常与手动采集在同一 writer 中保存独立窗口文件，并持久化本地索引。历史合计最多 12 条 / 64 MiB；自动单段最多 2 MiB，手动单段 16 MiB；活动记录受保护，较早记录按容量清理。旧索引与记录文件在启动时同步收敛到 12 条上限；重启后仍可逐条选择导出，未完成的手动采集标为中断。
6. 通用导出优先选择活动采集，其后选择最近记录；失败入口使用当次问题引用。ZIP 由 Rust 直接写到用户选择的位置，生产内容上限 32 MiB、开发 80 MiB，预留 256 KiB 元数据空间，超限保留最近范围并在清单标明。包内为 `runtime-trace.jsonl`、`manifest.json`、安全 `config-snapshot.json` 与 `summary.md`；原有 JSONL 接口继续供分析 / 回归使用。
7. 导出固定已打开文件的长度快照，主日志使用确认 flush 的截止序号，独立记录使用自己的连续序号并声明 `sequenceScope`。清单声明丢失、缺失、稀疏健康覆盖、采集 / 来源构建与导出器身份；配置快照明确为导出时配置。正在采集的记录可先导出可用前缀，之后继续补齐；取消保存保留记录，保存失败可重试。
8. 构建边界、认证、WebRTC、渲染、输入执行和发行隔离沿现有主线。导出复用生产核心投影、移除未知文本 / 身份字段、映射本地会话引用，包内省去绝对路径。用户说明 / 手工标记按实际诊断缺口扩展。

## Risks

- 稀疏健康落盘必须在包内明确覆盖，异常前文依赖有界缓冲；分析结论保持六段事实口径。
- 队列、IO、活动窗口与容量限制可能使证据部分可用，导出清单、记录截断标记和可用状态表达实际范围。
- 页面隐藏只影响显示刷新；后台任务状态与采集期限归 Rust 管理。
- 首版保持现有健康摘要构造与 IPC 的 1Hz 密度，常规 / 轻量主要减少持续写盘；健康分析以逐条 window/coverage 为依据。
- 配置快照为导出时安全配置；采集开始时完整配置固化和早期启动专用记录按后续实际需要扩展。
