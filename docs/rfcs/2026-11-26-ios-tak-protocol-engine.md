## Background

用户再次发现 GTA6 社区布局存在兼容问题，并要求从 TAK 与社区提取协议，建立通用解析与渲染能力。兼容单位确定为协议版本、字段形式、控件行为和渲染能力；游戏布局作为协议实例进入同一条处理链。

当前 iOS 使用 Rust 资源/引用处理、Swift 归一化/多指/绘制的原生兼容实现。better-xcloud 把社区对象直接交给官方 `LayoutCoordinator.changeLayoutForScope()`；正式 TAKX 则经过官方 schema 校验、历史转换和资源加载。两条入口共用运行时语义，社区入口还依赖省略字段的系统默认值以及宿主图集。

当前图标表包含官方 v4.1 schema 的 173 个语义名称及 A/B/X/Y 四个手柄图标名称，共177个。`TouchLayoutNormalizer.supportedIcons` 完全取该表的 key；Babylon 实际从 `atlas.frames` 建表，绘制通过 `getIcon(value)` 查询。已核对官方1/1.5/2/3/4五档DPI图集，名称均为234个，包含 GTA6 使用的 LT/LB/RT 及社区的 RB。该问题属于 iOS 目录遗漏官方运行时能力。

本轮固定社区修订 `4416b1ab07588a3244a5c02ce1fa5dfa64d8df74`，取得 92 个游戏定义、75 个模板、85 份布局。GTA6 `2035456122 → gta-vi/custom` 使用 `leftTrigger`、`leftBumper`、`rightTrigger` 图标；当前 iOS 校验会逐项记录 unsupported。社区全部模板中的四类手柄图标名称合计出现 74 次，属于共性能力缺口。

原始社区 JSON、两份哈希匹配的 TAK/Babylon 发布原件、协议结构清单和扫描结果归档到[方案证据](../../dev-docs/validation/2026-11-26-ios-tak-protocol-engine-plan/README.md)。统一编译、原生执行与渲染迁移已完成；结果归档到[实施报告](../reports/2026-11-26-ios-tak-protocol-engine.md)与[执行证据](../../dev-docs/validation/2026-11-26-ios-tak-protocol-engine/README.md)。

## Goal

1. 以官方 schema、历史转换器、TAK 控件状态机、Babylon 渲染属性及图集建立一个版本化协议合同。
2. 官方和社区来源编译成同一份规范化布局；解析、能力报告、输入执行与绘制消费同一合同。
3. 相同协议形式在全部游戏布局中获得相同行为；新增布局通过数据接入获得支持。
4. 使用整库批量编译及按协议能力组织的官方行为对照验证覆盖；兼容结论标明协议版本和宿主能力。
5. 可执行语义优先，协议框架约束；可选图标/样式/扩展字段采用默认回退，已知输入保持运行，能力缺口按控件或输出隔离。

## Scope

方案覆盖既有 `xbox-touch-layouts`、`xbox-ios-bridge` 与 iOS TouchControls。Rust 保持资源、纯数据转换和低频编译；Swift 保持屏幕几何、多指热路径、状态执行和 UIKit/Core Animation 呈现；输入沿 `StreamInputSession → XboxStreamDataChannels` 交付。

手柄布局、动态 Context/layer、资源、内置图标和样式为实施目标。鼠标、键盘、传感器沿用户上一轮暂缓决定保留独立能力分类。原生 pointer、媒体运行时和输入传输沿各自现有合同推进。本机记录利用保留的原文与资源重新编译获得升级。

## Protocol Contract

### 一份版本化能力来源

在现有 crate 内建立协议模块，登记 Layout/Manifest/Context 版本及别名、结构字段、枚举、可引用位置、默认值、历史转换、输入行为和渲染能力。schema 结构由冻结原件提取；默认值、状态机、合并与图标命名从官方运行时及宿主资源提取，每条行为附来源与版本。

schema 描述数据结构；TAK 源码提供动作、引用/patch、层合并、命中转交、轴变换及生命周期语义；Babylon 与宿主图集提供状态绘制、图片/图标名称、标签、透明度及变换语义。三类证据共同形成协议合同。

解析器、能力报告与 Swift 类型投影由同一合同生成或引用。编译产物携带 `irVersion`、`protocolRevision` 和 `requiredCapabilities`；每项声明能力同时登记解析、执行和绘制支持情况。

### 来源适配后统一编译

```text
官方 TAKX ─→ Manifest/资源/版本转换 ─┐
                                    ├→ 引用与状态解析 → 协议规范化 → Typed Layout IR
社区包装 ─→ 元数据/模板合并/默认值 ─┘
```

- 官方 profile：按明确版本选择校验器与转换器，统一旧 `icon`、`threshold`、上边缘槽位及历史方向动作。
- 社区 profile：提取 `schema_version`、名称、作者及模板身份，保留固定修订与顺序合并规则；按官方直接注入路径证明的运行时形式补齐默认值、处理宽容字段。
- 规范化：统一空槽、`blank`、cluster、action/axis 对象与数组、style 状态继承、颜色、资产及图标引用，保留原始 JSON Pointer。
- Context 更新：复用当前 Rust 引用解析和 JSON Patch，重新编译受影响内容；当前会话以匹配的 generation/scope/layout revision 接受结果。

社区宽容规则逐项引用官方运行时依据。现有源中 `toggle:"true"` 等形式进入行为对照后确定转换规则。未知形式输出精确路径和能力分类。

### 同一份 IR 驱动执行与绘制

IR 保留区域与槽位拓扑、稳定控件身份、类型化 action/axis、状态属性、默认样式、各状态覆盖、资源引用及必须能力。稳定身份由 scope/layout 与原始槽位路径构成，内容指纹用于判定输入释放和对象复用。

Swift 通过既有 UniFFI 接收粗粒度编译结果。几何层按控件类型与拓扑生成 socket 和命中区域；运行时根据类型化 action/axis 及状态合同执行。输入贡献合并、同键独立释放、轴限幅、切换 neutral 与后台抑制保持统一出口。

绘制消费标准控件状态与渲染描述，统一处理 shape、fill、stroke、image/icon、label、opacity 和 transform。默认样式和状态覆盖共用合并规则；CALayer/图片对象按稳定身份复用，属性变化触发局部更新。

图标目录来自官方宿主图集与语义图标合同的合并清单，区分图标名称、动作标签及资产 ID。图集资源通过统一资源快照消费；原生语义符号及标准动作标签提供缺失资源时的回退。GTA6 使用的手柄图标与其他布局共享解析和绘制能力。

### 统一诊断与缓存升级

兼容报告分别表达“可运行”和“完整兼容”，每条诊断带原文路径、版本及能力 ID。保存/预览/切换消费编译结果中的同一份报告，可运行布局允许预览、保存与切换。

- 已解析且已实现的 action/axis 持续执行；未知可选字段保留原文并生成 warning，当前运行消费已知字段。
- 图标、装饰图片、颜色及可选样式缺失时使用官方默认或动作标签；布局输入持续运行，视觉完整性单独报告。
- 未实现的控件、输出或暂缓的鼠标/键盘/传感器按能力隔离，已支持控件继续运行；整体失去有效输入时沿现有通用布局回退。
- 文档解析、资源/嵌套预算、会话与版本归属、可确定的输入输出语义保持硬边界。无法解释的操作保持能力诊断及隔离。

编译缓存 key 包含来源内容哈希、协议修订及 IR 版本。升级后利用保存的原文和资产重新编译；本机布局身份、来源署名及最近选择继续关联现有记录。

## Risks

- schema、运行时与图集有各自发布修订；联合清单和哈希保证合同可追溯，更新时生成能力差异。
- 社区直接注入形式依赖运行时宽容行为；实际源码和行为回放作为规范化依据。
- IR 迁移影响动态更新与旧输入释放；稳定身份、内容指纹、会话代次及编译缓存版本共同维持交接。
