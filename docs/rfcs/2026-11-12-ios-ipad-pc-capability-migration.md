## Background

[迁移评估](../isu/2026-11-12-pc-to-ios-app-migration-feasibility.md)确认现有 SwiftUI + UniFFI + Rust + libwebrtc/Metal 可承接 PC 主线能力。当前 iOS 保留旧四 Tab 和集中式设置，缺少控制器工具与 PC 新菜单接线；主机错误/目录排序、设置投影及触屏输入需要一起收敛。

## Goal

交付五个可用主菜单、移动端原生设置层级，以及主机、我的、云游戏和控制器的页面与数据接口能力；串流发起的授权、资格、排队、主机唤醒、会话 HTTP 流程与 PC 对齐。当前阶段聚焦页面和前置流程，音视频运行渲染沿既有实现进入后续验收。功能语义以当前 PC 为标杆，布局、输入、系统音量、存储和生命周期按 Apple 平台实现；iPhone 与 iPad 共用数据与页面模块。

## Scope

- 主导航固定“主机 / 云游戏 / 我的 / 控制器 / 设置”，默认主机，保留各菜单状态与返回位置。
- iPhone：二级分类/工具统一通过 NavigationStack 进入子页面，支持系统返回与边缘返回手势。
- iPad 可用宽度达到 900pt 且为常规字号时采用 260pt 左侧二级菜单与右侧子页面；手机、窄分屏和辅助字号使用 NavigationStack 子页面。同一返回栈和选择跨窗口变化保留。
- 视觉沿当前 PC 的中性色板、compact/narrow 正文、6/8/10pt 圆角、16/24/32pt 间距、方形游戏封面、主机卡片和设置独立行；透明表面使用半透明渐变、细边框和轻阴影。按用户 2026-11-16 新参考图提高深色画布和内容块明度，一级页标题 24pt、分区/子页 18pt、正文 14pt；小于 360pt 的窄屏采用统一紧凑字号，开关视觉缩放至 82%。底栏直接复用 PC 原始 Xbox 图形，二级入口与页操作采用 Fluent，详见当前视觉合同。
- 2026-11-16 布局合同：采用上中下三段式，上段左侧登录用户头像与当前页标题、右侧当前页操作，子页以纯图标返回替换头像；中段页面纵向滚动；下段固定五个纯图标一级导航，按用户最新要求增加带背景模糊的半透明底色与边界。顶部和中部共用透明连续背景，卡片与内容块使用独立表面，详见 [视觉合同](../../iosapp/DESIGN.md)。
- 主机：选择/设备事实/缓存即显/刷新/电源/安装游戏子页/基础串流入口。
- 云游戏：目录栏目、搜索/筛选、收藏、稳定游戏身份与详情/游玩；复用共享 Rust 查询和已有缓存，保留合法空结果与部分失败。
- 我的：账户、好友、成就、游玩统计与 Xbox 相册按原生子页面/二级分类装配，查询和分页沿公共 API。
- 控制器：连接与实时输入、游戏输入设置、独立 Y 反转/死区、四路震动及菜单操作；设备能力按 GameController 实际暴露内容提供。
- 设置：通用、串流体验、连接与主机、高级诊断及关于；外观/图标/登录、语言、云/主机分辨率、H.264、码率、授权地区/串流服务器/目录市场、IPv6/TURN、画面适应与音频操作使用正确生效时机。
- 基础串流：沿现有 Rust session 与单一 libwebrtc/Metal，接入支持设置、实体手柄与基础虚拟触屏手柄；取消/失败/重试、菜单接管、后台/退出释放具有完整终态。
- 串流装配固定为公共 Rust session/信令 + libwebrtc 解码 + 自定义 Metal 上屏；WebRTC/Metal 为必需构建依赖，删除缺库空 runtime、黑屏占位 surface 和通用对象轨道适配。Device 的 CVPixelBuffer 零拷贝导入与 Simulator 的 I420 三平面上传共用现有 mailbox、scheduler、presenter 和 trace 合同。
- 本轮产品输入按触屏和手柄组织；键盘映射、键鼠串流及键盘快捷键排除在迁移范围外。文字输入使用系统原生文本控件。
- 后续能力：官方 TAK、SR/锐化/风格效果链、远程安装/卸载、Share 协议试验与桌面更新安装属于各自独立任务。

## Architecture / UX Contracts

1. PC 继续 Tauri + Vue + Rust；iOS 延续现有 SwiftUI、UniFFI、libwebrtc/Metal 与 GameController。认证、Xbox API、会话/信令及 wire 权威复用现有 Rust crates。
   iOS 串流采用 PC 稳定路线的职责分工：标准 WebRTC 负责传输、反馈与解码，自定义 renderer 负责 decode 后 latest-only 与真实 present；生产 target 直接装配唯一 libwebrtc/Metal 实现，测试替身仅用于 XCTest。
2. 在现有 bridge 内扩展稳定 DTO 和粗粒度 API；平台存储、UI 状态、音量和输入热路径保持 Apple 适配，设备与查询身份分别处理。
3. 页面按可用宽度、大字号和安全区适配。交互区域至少 44pt；宽布局收紧内容最大宽度和卡片尺寸，所有分类共用一个内容实现。
4. 异步提交携带当前账户/请求代次，旧响应隔离；刷新保留最近成功内容与选中身份，空列表与 typed failure 分别表达。
5. 触屏和手柄沿同一逻辑输出及既有 DataChannel 编码。菜单、录入、设备切换、后台和停止清理输入/触觉；手柄优先与触屏接管按明确来源规则切换。
6. 设置生效时机明确：外观/本地输入即时；连接/codec/码率/分辨率在下一连接；授权地区在下一授权。云服务器与授权地区、目录市场使用独立合同。
7. 两种设备共用内容实现和数据 owner；宽屏二级侧栏位于同一 NavigationStack 外，窗口变化保留分类、返回和在途请求归属。
8. 实现期间持续推进，统一在全部代码完成后执行编译、回归及模拟器布局检查；真实账号、设备串流与长测由用户在最终交付后验收。

## Risks

- 微软资格/隐私/主机状态与媒体有效期随真实账户和服务变化，页面保留来源、缺值与真实失败。
- iPad 窗口变化与横竖屏切换可能改变导航装配，页面选择和异步 owner 需要独立于具体列布局。
- Swift 6 actor 隔离与原生 WebRTC 回调队列需保持现有接收、latest-only 和 cleanup 约束。
