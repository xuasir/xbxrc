# iOS Trace 采集可靠性与性能口径补齐

状态：Done。用户于 2026-11-20 明确授权上一回复的前四项修复；实现与自动验证已完成。交付见[Report](../reports/2026-11-20-ios-trace-reliability.md)及[证据](../../dev-docs/validation/2026-11-20-ios-trace-reliability/README.md)。

范围：现有 Swift writer、轻量采样、RTC/display 统计、队列压力和源时间。日志继续通过既有导出入口保存到 `runtime-logs/ios`。传输、会话与媒体调度继续沿当前实现；分析门禁深化属于审计清单的第五项。

## 实施合同

1. 打开/写入/sync 失败保留明确状态与计数，失效句柄关闭，按限频重开；写入失败精确统计未写行，避免无限积压。恢复写入记录失败及丢失摘要，导出在故障状态下返回明确错误。
2. 轻量模式保留 essential/key 健康快照，对指定逐帧事件按累计计数有界采样，首次事件仍保留。
3. RTC 接收/丢包采用同一视频范围，Trace 补充源样本时间、received/decoded 计数和统计窗口。display delta 由定期 Trace 样本差分产生；GPU 完成回调时间在回调入口采样，drawable 呈现使用系统 presentedTime 独立观测，并标记来源、窗口及样本数。
4. 所有事件入口捕获源时间，写入队列采用硬容量与关键锚点预留；压力丢弃计数合并，flush/导出/关闭输出尾部摘要。单行与编码缓冲拥有字节上限。
