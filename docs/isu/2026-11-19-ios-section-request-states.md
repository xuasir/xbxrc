# iOS 信息页分区请求状态与局部重试设计

日期：2026-11-19。状态：设计建议。来源：用户要求 iOS 信息页面按接口分区表达请求错误，使用可理解的区块状态和重试操作。

## 1. 问题定义

信息页由多个来源组成，用户需要同时看清已取得的内容、暂时缺失的内容以及恢复操作。错误提示的位置跟随受影响的信息区块，错误文案说明当前情况，重试范围对应具体来源。

本轮设计覆盖我的概况、好友与玩家详情、个人游戏与成就、安装库、云游戏详情和相册。信息页入口、原生返回栈、身份/媒体区和底部导航沿现有布局合同。云目录栏目接入同一规则，作为后续独立阶段。

核心交付目标：

- 成功区块持续展示；失败区块在自己的位置表达状态。
- 用户看到简短原因、保留内容的情况和明确恢复动作。
- 请求成功、成功空结果、服务缺少字段、首次失败、刷新失败、分页失败具有明确语义。
- 单区块重试、当前页刷新和共享认证恢复各自具有可验证的请求范围。

## 3. 可选路径

| 路径 | 价值 | 成本与覆盖 |
| --- | --- | --- |
| 页面层统一短文案和重试组件 | 能快速修正技术错误曝光和缺少重试入口 | 聚合接口保留现有失败粒度，安装库和账户辅助来源仍需后续数据合同补齐。 |
| 来源状态贯通 Rust → Swift Store → 信息分区（推荐） | 区块失败、缓存时效、定向重试和分页恢复完整闭环 | 涉及 iOS bridge 合同和多页迁移，按复杂任务先形成 RFC，再分阶段执行。 |
| 引入通用请求管理框架 | 可统一更多请求生命周期 | 涉及现有 Store 归属与认证协调的广泛调整；当前任务优先沿既有状态模型扩展。 |

## 4. 推荐方向

### 4.1 提示位置与视觉

提示组件使用“图标 + 简短标题 + 一句说明 + 一个恢复动作”。首次失败使用普通正文和局部状态区域，刷新失败使用紧凑透明提示，分页失败放在列表末尾。图标和文字共同表达状态，强调色仅用于提示图标及必要动作。

| 场景 | 提示位置 | 展示与操作 |
| --- | --- | --- |
| 首次载入 | 保留分区标题，在原内容槽位展示占位/进度 | 数量、分数、时间以占位表达，成功后提交真实数值。 |
| 首次失败 | 分区标题下，承接原内容位置 | “游玩统计暂时无法载入”＋“暂时无法连接 Xbox 服务，请稍后重试。”＋“重试”。 |
| 成功空结果 | 分区内容位置 | “暂无游玩记录”等业务空态；筛选空结果提供清除筛选。 |
| 有内容时刷新 | 分区标题附近的小型忙碌标记 | 原内容继续可用；更新完成后局部替换。 |
| 刷新失败 | 分区标题下、已保留内容上方 | “更新失败，当前显示上次内容。”＋上次成功时间＋“重试更新”。 |
| 分页失败 | 列表/网格末尾，接替载入更多的位置 | “更多记录暂时无法载入，已加载内容可继续查看。”＋“重试加载更多”。 |
| 服务成功但字段缺失 | 对应事实/指标位置 | “资料暂缺”“时长暂缺”或 `—`；明确服务覆盖说明可保留。 |
| 登录恢复需要用户操作 | 当前账户页面上部的一处共享提示 | “登录状态需要更新，请重新登录后继续加载。”＋“重新登录”；区块保留来源状态和同账户可展示内容。 |
| 操作失败 | 电源、下载、分享等动作旁 | 说明动作结果与可恢复方式，内容查询状态沿各自分区保留。 |

分区标题 18pt，失败标题/主体 14pt，补充说明和更新时间 12pt；窄屏按自然高度换行。标题与内容 12pt、说明与正文 4/8pt、独立分区 32pt，所有按钮触屏区域至少 44pt。状态始终留在相同分区位置，忙碌时禁用该恢复按钮并显示进度。

### 4.2 按页面确定失败边界

| 页面 | 独立状态/来源 | 具体提示位置与重试归属 |
| --- | --- | --- |
| 我的 | 基础资料、在线状态、社交计数、游戏与成就概况 | 基础资料在身份区；在线状态在姓名/活动处；社交计数在指标行下；游戏概况在概况标题下。只补发失败来源。 |
| 好友/玩家详情 | 好友列表、玩家资料、最近游玩 | 列表状态在好友内容区；玩家资料紧随身份；最近游玩位于自己的标题下。资料重试只请求资料，历史重试只请求历史。 |
| 个人游戏 | 游戏记录、时长、成就列表、截图、游戏片段 | 游戏记录在概览；时长在统计/时长信息处；成就在自己的列表；相册按媒体来源。统计汇总标注已覆盖范围和缺失数量。 |
| 成就对比 | 我的成就、玩家成就，分别保留分页状态 | 来源提示靠近对比列表及相应标题；可用一方持续展示。缺失一方用 `—`/“状态待载入”，筛选和比较结论仅使用已知状态。 |
| 安装库 | 安装游戏、存储、主机状态、封面补全 | 存储错误留在上半区存储摘要；主机状态错误留在设备事实处；安装游戏错误留在下半区列表；单张封面使用图片回退，批量补全失败在媒体区给一条提示。 |
| 云游戏详情 | 商品资料、个人游戏记录、排队时间 | 商品资料在“关于游戏”所在来源组；个人记录在“我的游戏记录”；排队状态紧邻游玩按钮。“重试查询等待时间”只查询等待时间。 |
| 相册 | 截图、游戏片段、单个媒体链接/播放/下载 | 全部媒体模式在媒体区显示来源名称和局部失败；单类模式在该内容区显示；链接/播放失败在预览位置；下一页失败在页尾。 |
| 云目录（后续阶段） | 基础目录、最近游玩、新增、热门、即将离库、商品补全 | 来源状态移至对应栏目；头部只保留目录级同步/认证状态；单栏目恢复使用现有 Rust 查询能力。 |

**一个请求产生多个展示子区时，来源状态共享。** 商品详情中的简介、截图列表、语言和无障碍都由同一接口提供，使用一个“游戏资料”恢复边界，组内子区保留可用数据或简短占位。该来源组提供一个明确重试入口。截图本体下载拥有自己的图片/预览失败状态。

**多个请求产生一个展示分区时，保留子来源状态。** 社交指标由社交摘要和好友数量组成，失败指标表达待载入并给出来源级恢复入口；成功指标保持真实数值。成功空数组和已知 0 都属于成功事实。

**相册先呈现成功来源。** 全部媒体模式持续展示已取得的截图或片段，提示另一来源正在载入/暂时失败；显示“当前内容尚在补齐”。新增结果按稳定媒体身份去重和捕获时间合并，保留当前滚动锚点；跨来源时间水位在已完成来源间维持已覆盖区间语义。

### 4.3 错误语义与文案

Rust bridge 交付稳定错误类别、恢复策略及来源；Swift 通过 string catalog 投影面向用户的文案。接口 message、NSError 描述和 response body 进入既有诊断路径，页面文案来自有限的本地文案集合。

| 已确认的事实 | 用户说明示例 | 恢复动作 |
| --- | --- | --- |
| 网络连接中断 | “网络连接已中断，请检查连接后重试。” | 重试 |
| 请求超时 | “Xbox 服务响应较慢，请稍后重试。” | 重试 |
| 临时服务失败 | “Xbox 服务暂时无法提供这部分资料，请稍后重试。” | 重试 |
| 限流且有 Retry-After | “请求较频繁，请稍后再试。” | 冷却结束后重试；剩余时间按明确服务事实呈现。 |
| 认证恢复失败，需要登录 | “登录状态需要更新，请重新登录后继续加载。” | 重新登录，沿现有 AuthStore 恢复。 |
| 服务明确返回隐私限制 | “该玩家的这部分资料受隐私设置限制。” | 查看说明；再次检查作为次级动作。 |
| 普通访问拒绝 | “当前账户暂时无法访问这部分资料。” | 检查账户/访问条件；再次检查。 |
| 明确不提供该数据 | “Xbox 暂未提供这款游戏的游玩时长。” | 显示覆盖说明。 |
| 响应解析/分页协议异常、未知错误 | “这部分资料暂时无法载入，请稍后重试。” | 按故障恢复策略重试或刷新列表。 |

普通 403 归入访问受限，具体订阅、地区、隐私结论由明确 service code 支撑。401 进入现有凭据协调与有界续期，续期成功后重试原来源；需要重新登录时汇成一个账户提示。用户主动取消和过期请求返回上一稳定状态，终止本次忙碌。

### 4.4 现有状态模型的扩展

沿 `XboxNativeDataState`、`XboxSingleDataState`、`XboxInstalledLibraryState` 和现有 AuthStore/CloudLibraryStore 扩展，继续使用当前请求去重与 ownerGeneration/scope 身份校验。

需要表达的最小事实：

| 事实 | 用途 |
| --- | --- |
| 成功快照存在性，以及内容/空结果 | 首次失败与刷新失败的判定；成功返回 `[]` 或可选值缺失依然提交成功事实。 |
| 当前请求阶段：首次、刷新、下一页 | 决定提示位置和恢复方式；页尾重试消费原 continuation。 |
| 结构化 `failure`：kind、recovery、source、attemptKind、可选 retryAfter | 稳定文案映射与来源级恢复；状态模型按事实保存。 |
| 每个来源的 updatedAt | 只在该来源成功提交时更新；部分失败继续呈现旧成功时间。 |
| 同一来源当前 requestID 与 scope | 合并重复触发，隔离跨账户/玩家/主机/语言/地区的迟到结果。 |

View 层从这些事实派生“加载、内容、空、首次失败、保留内容的更新失败、页尾失败”，组件负责渲染；页面负责提供有类型的恢复动作。错误字符串逐页迁移到结构化 failure，完成迁移后清理对应页面的直接渲染调用。

复合响应中的 `games/storage/powerState` 改为各片段的结果与来源状态。成功片段提交新值及时间，失败片段保留旧值及自己的 failure。`notices` 中的覆盖说明、商品封面补全状态与请求失败分别拥有明确类别。

账户资料复合请求保留 profile/social/friendCount/presence 的各自结果。沿现有 Rust API helper 支持指定来源集合，初次并行取得当前页需要的来源，局部重试只发目标来源。各来源可按既有异步 bridge 查询分别提交，使基础身份和可用区块及时出现；聚合查询复用相同 helper。

建议文件责任：

- `crates/xbox-ios-bridge/src/lib.rs`、`personal.rs`、`personal_queries.rs`、`cloud_queries.rs`：类型化失败、复合结果与来源选择，底层 Xbox API/HTTP 继续由公共 Rust 承接。
- `iosapp/XBXRC/Platform/RustBridge/*DataClient.swift`：投影 FFI 结果/错误；生成绑定由已有脚本再生。
- `Shared/Models/PersonalDataModels.swift`、`Shared/State/Xbox*Data*.swift`、`CloudLibraryStore.swift`、`Features/Authentication/AuthStore.swift`：保存失败和来源快照，复用请求身份与认证协调。
- 新增 `Shared/Components/AppSectionRequestState.swift` 与 `Shared/Models/SectionRequestFailure.swift`：局部状态呈现与文案映射；继续复用 AppInformationPage 和主题令牌。
- `Features/Profile`、`Features/Achievements`、`Features/Hosts`、`Features/Library`、`Resources/Localizable.xcstrings`：页面迁移、中英可见文案及无障碍名称。

### 4.5 重试与刷新合同

1. 局部“重试”调用明确来源查询，携带当前 owner、玩家/主机/商品、locale/地区和原请求阶段。
2. “重试加载更多”继续原 continuation；成功后按稳定 ID 追加，失败时保留已加载列表和游标。重复 continuation 由既有协议保护识别，并提供“刷新列表”恢复动作。
3. 右上角刷新/下拉刷新并行更新当前可见页面的数据；成功与失败独立提交。个人游戏刷新作用于当前选中的概览/成就/相册/统计内容，已访问分页范围沿现有刷新合同处理。
4. 同来源重复触发共用在途请求；各来源的忙碌互相独立。限流冷却使用服务事实，临时网络恢复保留用户可操作入口。
5. 首版采用进入页面加载、现有 Rust 有界重试、用户主动重试；后续自动恢复需求单独评估。登录续期继续沿现有授权流程。
6. 账户切换清空相关快照和失败；主机、玩家、语言/地区切换使用对应 scope。旧响应仅完成旧请求生命周期。
7. 商品资料或等待时间失败时，游玩能力继续由现有访问资格/会话启动合同决定；排队估计属于辅助信息。主机状态未知时保留现有远程游玩校验和电源动作事实。

### 4.6 验收标准

| 验收用例 | 通过标准 |
| --- | --- |
| 多来源中一个失败 | 对应区块出现原因和恢复入口，其他区块继续展示成功内容。 |
| 每来源首次成功空结果后刷新失败 | 原业务空态保留，并显示更新失败及上次成功时间；真实 0 与加载占位分开。 |
| 安装库游戏成功/存储失败/主机状态成功 | 游戏列表与设备事实可用，错误留在存储区域，重试仅请求存储来源。 |
| 账户基础资料成功、在线状态或社交来源失败 | 身份正常呈现，失败来源待载入且可恢复，成功指标保持真实值。 |
| 已有内容后刷新失败 | 保留内容、筛选、滚动和上次成功时间；成功区块独立更新。 |
| 下一页失败后重试 | 页尾显示提示，消费同一 continuation，已有条目/游标保持，成功后无重复追加。 |
| 成就对比一方失败 | 可用一方持续呈现；未知一方明确为待载入，筛选和比较只使用已知事实。 |
| 相册一个来源仍加载或失败 | 成功来源及时可见，局部重试只补发目标媒体类型；合并时去重且滚动锚点稳定。 |
| 同来源连续点击/取消/退出页面/切换账户与 scope | 在途请求合并，busy 结束，迟到响应按归属隔离；新的来源状态正确保留。 |
| 401/403/429/timeout/unknown | 登录提示按账户汇总，普通拒绝使用访问受限，限流沿明确冷却；其余映射稳定短文案。 |
| 错误中带 URL、token、技术描述 | 可见文字与无障碍内容仅来自本地文案；诊断按既有脱敏策略记录来源、类别、结果与 operationId。 |
| 手机/iPad、320pt、大字号、深浅、中英、VoiceOver | 文案完整换行，按钮至少44pt，列表末项及局部重试可达；恢复结果通过局部可访问状态播报。 |

使用现有 `PCDataParityTests`、`PCPageUITestFixtures`、`PCPageInteractionTests` 注入确定性的首次/刷新/分页及复合来源失败，断言请求次数、scope、continuation、结果提交与按钮可用性。Rust 验证复合响应部分失败和类型化错误；真实账户的服务文案、隐私和认证恢复沿实机验收。

## 5. 待验证事实与默认决策

- 普通 403 使用访问受限文案；特定隐私/权益/地区提示以服务明确错误码为准。执行时梳理现有 WebApiError 中可稳定取得的分类和 Retry-After。
- 商品资料保持一个请求来源组，组内简介/媒体列表/语言/无障碍共享状态；单个媒体下载/播放各自独立。
- 账户资料和安装库当前为聚合 bridge 调用；执行时采用来源选择与共享 Rust helper，验证基础资料及时展示和局部重试请求范围。
- 云目录来源已有 unavailableSources；按同一原则扩展来源失败与更新时间后，进入独立栏目迁移阶段。

当前设计可进入 RFC；服务错误码样本和 bridge 导出细节在执行准备阶段核验。
