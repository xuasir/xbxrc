# 默认直通引擎与可组合画面处理

日期：2026-11-10；主窗口单窗口设计。来源：用户要求默认提供直通引擎，保留仅在渲染异常时使用的降级开关，并允许 SR、锐化、风格组合。

## 问题与目标

ROG 掌机上的用户反馈为原生 video 掉帧、锐化与 SR 流畅。当前代码中原画选择原生 video，增强选择逐解码帧驱动的 WebGL。`render_mode = video | sharpen | sr` 同时承担引擎选择与效果选择，关闭增强也会切换呈现路径。

推荐默认原画、SR、锐化和风格共用逐解码帧 WebGL 引擎，用户按需组合效果；原生 video 承担兼容降级。

## 当前约束

- 保持 Browser WebRTC 接收和浏览器解码，复用已实现的主线程/Worker VideoFrame 供给、latest-only 预算和现有 WebGL shader。
- 复用当前 Vue 画面面板、会话覆盖、保存默认、几何导航和 A/B 临时恢复。
- 锐化核按处理图像的 1:1 像素工作，输出保持既有真实源尺寸下限；实际放大才执行 SR 重建。
- ROG 反馈支持呈现路径差异，具体 Windows 合成、驱动与物理上屏原因仍需设备证据。既有本地自动验证继续作为供给基础。

## 可选方向

| 方向 | 效果 | 成本与边界 |
| --- | --- | --- |
| 原画切到现有 WebGL，保留三模式 | 原画获得独立帧供给 | SR 与锐化继续受单一模式限制，后续组合仍需改造 |
| 默认统一直通，后处理独立，video 兼容降级 | 所有日常显示共用同一供给，画面选项可组合 | 需要同步配置合同、处理计划、状态与控件 |

## 推荐方向

采用第二项：引擎只有默认直通与兼容呈现；SR、锐化和风格形成独立用户意图。默认全部效果关闭，零效果时只上传与显示原画。

处理顺序为解码帧导入、按需 SR 重建、一次共享锐化、颜色风格、视口呈现。SR 的现有 RCAS 与常规锐化收敛到一个按用户选择执行的锐化阶段。兼容降级暂停全部后处理并保留配置。

手动降级默认关闭，沿当前“应用本次 / 保存默认”范围生效；接口或 GPU 硬故障自动保证基础画面并显示实际原因。帧率波动保留诊断、提醒和用户选择，实际引擎的迁移由兼容意图或明确故障驱动。

## 后续需要的证据

- 组合 SR 与锐化时，统一锐化在重建尺寸上工作的观感与 GPU 成本。
- ROG 原画直通的实际改善和其他 Windows 设备的能力回退。

上述事项进入实施后的局部回归和用户实机验收，当前设计沿已明确的默认方向推进。
