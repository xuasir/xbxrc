# 串流错误提示与弹窗体验优化规划

## 问题定义

本轮围绕桌面串流的交互、样式与展示信息展开。目标是让玩家及时知道发生了什么、串流是否仍在运行、接下来可以做什么，并能在需要时提供准确的诊断信息。

范围覆盖 xHome / xCloud 的启动、连接、首帧等待、播放中恢复、会话终止，以及串流菜单内的文本发送、显示设置、麦克风、截图导出和关机失败。当前工作停留在规划与场景预览；开发由后续 `task-run` 承接。

### 当前实现确认的问题

| 优先级 | 源码确认的行为 | 用户影响 | 规划方向 |
| --- | --- | --- | --- |
| P0 | `session.ts` 将结构化错误统一转为 `startFailed`，返回值保留文案与摘要，丢失 `errorKind`、`retryable` 和启动阶段。 | 登录失效、主机注册、网络和运行时问题在动作层合并，页面统一给出重试。 | 保留结构化分类、阶段与重试依据，按问题选择动作。 |
| P0 | `useStreamExecution.ts` 把 connection failed / closed 翻译成正文，再送入依赖原始字符串标识的 `resolveStreamError`。 | 这条路径可落入 `unknown`；同类故障通过不同入口呈现不同界面。 | 先规范化错误身份，再完成本地化与页面投影。 |
| P0 | `Stream.vue` 的连接失败 sheet 固定使用 NAT、公网 IPv4/IPv6 和 9002/3074 转发说明，仅提供退出；其他错误使用带重试的全屏错误层。 | 诊断引导与实际故障来源可能错位；连接失败路径的恢复入口不一致。 | 统一终态错误卡，帮助信息按 home/cloud 和证据匹配。 |
| P0 | `resolveStreamError` 的未知分支直接返回原始字符串，`remoteConsoleNotReady` 将 details 拼入正文；错误层直接展示 `errorDiagnosticText`。 | 玩家正文出现内部标识、状态串或重复诊断说明。 | 玩家摘要、处理建议与技术详情分层，未知错误使用稳定的本地化兜底。 |
| P0 | `StreamAlertSheet` 点击遮罩与 B 返回均触发 close；failed sheet 的 close / select 都导航离开串流。 | 点击空白即退出；动作后果与明确按钮的表达存在差距。 | 终态卡遮罩保持卡片，B/Esc 对应可见的“返回列表”。 |
| P1 | “长时间无画面”共用一套文案和 60 秒计时；frameReady 清除计时，首帧后停滞的覆盖需结合既有监督事实核对。 | 首帧等待与播放后停滞容易使用同一种解释；警告覆盖面与恢复阶段需澄清。 | 将首帧等待、播放停滞与恢复中分别投影，先沿用现有期限。 |
| P1 | 文本发送返回 false 后仅结束 loading；显示设置保存异常沿 Promise 抛出；截图导出另有独立错误 sheet。 | 局部操作失败的反馈和后续动作分散。 | 在来源面板保留草稿和错误，明确重试 / 关闭；终态提示统一接管优先级。 |
| P1 | 错误触发后立即走现有 closeExecution；关闭完成会清空 session / health / execution。 | 用户打开详情时，现场信息可能已经释放。 | 在清理前固定一份脱敏失败快照，错误卡与复制操作读取该快照。 |

以上为可达源码路径与展示缺口。各类问题的发生频率、真实根因和恢复效果由后续故障注入及实机 trace 验证。

## 当前约束与依据

- 本轮以 `main` 的 Browser 串流为实施基线。Vue 3 + TypeScript 负责提示投影与交互，Rust 公共层负责认证、Xbox API、会话与信令事实。
- 复用 `useStreamExecution`、现有 view-state reducer、runtime-host、FocusScope / Focusable、InputController 与串流输入路由；提示状态放在现有页面 UI 所有者中。
- 现有自动恢复、TURN fallback、注册补偿、single-flight、attempt / generation 过滤、统一清理和重试门槛继续作为执行依据。
- 后端 `retryable` 是现有错误合同中的默认依据。自动补偿耗尽、可立即手动重试、需修复前置条件后再连接分别明确；相关语义在实施 RFC 中逐类固定。
- [公共可靠性 RFC](../rfcs/2026-10-28-streaming-common-reliability-simplification.md)已确立控制面观测错误、真实终态、播放事实和有界清理的职责。正常云排队与短暂观测失败保持原有业务处理。
- [主机注册补偿 RFC](../rfcs/2026-03-24-home-session-server-registration-retry-compensation.md)要求显式服务端证据驱动补偿。主机配置建议与人工操作按已确认原因提供。
- [串流指标方案](2026-11-03-stream-metrics-low-interference-design.md)已将运行状态与诊断详情分层。本轮与其共用事实口径和条件状态提示，错误详情保留失败时刻的快照。
- 样式沿用当前主题语义变量、浮层材质和焦点效果；覆盖深浅主题、窗口化、全屏和窄窗口。
- macOS 最低要求保持 26.0，实机启动、串流与长测由用户手动验收。

## 方案比较

| 方案 | 内容 | 收益与代价 |
| --- | --- | --- |
| 文案和样式修整 | 优化当前两套错误界面与正文，补按钮 | 可以快速改善阅读；分类、动作和弹层竞争仍需后续治理 |
| 统一错误投影与分级提示 | 保留错误身份，建立场景映射，复用当前执行流程与 UI owner | 同时改善解释、动作、干扰和诊断；需系统验证终态、清理和输入交接 |
| 全应用提示系统重构 | 串流、设置、登录、更新共用全局错误中心 | 跨页面一致性更强；范围扩展至全局状态和基础设施 |

推荐“统一错误投影与分级提示”，实施范围限定在串流。

## 推荐方向

### 1. 按影响选择展示形式

| 层级 | 适用情况 | 展示与交互 |
| --- | --- | --- |
| 被动状态 | 自动恢复、短暂网络波动、现有供给恢复 | 共用条件状态条；保持游戏输入；恢复后自动收起 |
| 局部操作错误 | 文本发送、显示保存、麦克风操作、导出失败 | 来源面板内展示错误、保留输入 / 草稿，提供对应重试；独立导出使用小型可关闭提示 |
| 持续等待警告 | 连接仍存活，持续等待首帧 / 当前画面 | 条件提示提供“查看问题”入口，用户主动打开可操作卡；等待与结束动作清晰可见 |
| 终态错误 | 启动失败、恢复耗尽、远端会话结束、会话资源失效 | 页面中央统一错误卡，集中提供恢复动作、返回列表、诊断详情 |

等待和恢复的升级条件读取现有事实与期限。首版保留当前 60 秒无画面警告、连接 / 恢复预算与远端生命周期判定；展示节流与合并仅影响 UI。正常排队继续展示排队进度。

### 2. 玩家正文固定回答三个问题

每张卡采用“发生了什么 → 当前影响 → 建议动作”的顺序。

- 标题：使用“连接已中断”“登录已过期”“主机仍在准备”“连接已建立，正在等待画面”等具体状态。
- 正文：1–2 句，说明串流当前状态，并依据已确认事实提供一项优先建议。
- 动作：一个主动作、一个返回 / 关闭动作，详情作为低强调入口；按钮明确表达“重新连接”“重新登录”“返回主机列表”“返回游戏列表”。

首次连接失败与播放后中断分别使用“连接失败”“连接已中断”。无首帧与播放后停滞分别描述“等待首帧”“画面暂时停滞”。只有故障事实支持时才给出登录、主机注册、权限和网络配置等具体归因。通用失败描述保留原因待确认的准确边界。

### 3. 错误场景与动作矩阵

下表为目标展示文案；终态与动作资格由当前业务合同确定。

| 场景 | 建议标题 / 说明 | 主动作 | 其他动作与条件 |
| --- | --- | --- | --- |
| 认证失效 | 登录已过期；恢复登录后可重新连接 | 重新登录 | 清理旧串流后进入现有登录流程；返回对应列表 |
| 主机唤醒 / 远程游玩准备 | 主机仍在准备；按明确原因检查主机电源或远程游玩状态 | 返回主机列表 | 查看对应检查指引；准备完成后从列表重新连接 |
| 主机注册补偿耗尽 | 主机串流服务仍在准备；说明本轮补偿已结束 | 返回主机列表 | 等待主机就绪后再连接；保留补偿次数于详情 |
| 云会话创建 / 准备失败 | 云游戏启动失败；本次会话已结束 | 重新连接 | 依据 retryable；返回游戏列表；重新排队的影响明确提示 |
| 正常云排队 | 正在排队；展示真实 ETA / 等待状态 | 取消排队 | 沿用排队 UI 与取消流程 |
| 网络 / ICE / 协商终态失败 | 连接失败，或连接已中断；说明本次连接已结束 | 重新连接 | 依据当前恢复 / 清理结果；网络检查作为帮助入口 |
| 持续等待首帧 | 连接已建立，正在等待画面 | 继续等待 | 查看问题、结束串流；实际首帧到达自动收起 |
| 播放后停滞 / 恢复中 | 画面暂时停滞 / 正在恢复连接 | 由现有恢复处理 | 轻提示；只有既有终态事实进入错误卡 |
| 播放器 / 解码初始化终态失败 | 播放器启动失败；本次串流已结束 | 重新连接 | 仅在重试资格成立时显示；兼容性建议按能力证据提供 |
| 远端主动结束 / 资源失效 | 串流已结束 / 会话已结束 | 返回对应列表 | 新建会话入口按具体原因与资格提供 |
| 旧资源仍在清理 | 正在结束上一轮连接 | 返回对应列表 | 显示清理状态；新连接资格由既有清理 gate 给出 |
| 文本、显示保存、麦克风、截图失败 | 具体操作失败，并说明仍保留的状态 | 重试该操作 | 保留草稿 / 当前有效设置；详情按需展开 |
| 关机请求失败 | 关机请求失败；本地串流结束状态与主机命令结果分别说明 | 返回主机列表 | 主机命令重试独立处理，资格来自当前控制能力 |
| 未分类终态错误 | 串流发生异常；本次串流已结束 | 返回对应列表 | 复制诊断；重新连接入口使用明确资格 |

“重新连接”沿用当前结束旧会话再创建新会话的行为。正文按真实影响说明新建会话与重新排队；游戏进度和远端运行状态以服务事实为准。

### 4. 交互规则

- 终态卡显示期间集中提供主要动作。遮罩点击保持卡片；B/Esc 对应可见的返回列表按钮。详情展开后，B/Esc 优先回到问题摘要。
- 局部错误的 B/Esc 关闭当前提示并恢复来源焦点；文本 / 设置面板保留草稿。警告的“继续等待”恢复原游戏输入，告警 latch 绑定当前会话与同一故障过程。
- 终态接管正在打开的菜单和功能 sheet，清理旧 UI 捕获原因；同一时刻由一个最上层交互面板持有焦点。恢复轻提示保持被动。
- 重试、登录、返回和复制均有处理中 / 成功 / 失败反馈；重试复用当前 single-flight。清理耗时、清理未完成与下一步资格清晰可见。
- 错误出现时固定 incident 身份与现场快照；同一故障过程只建立一张卡，附带事件更新详情。新 attempt 的迟到错误由既有 generation 规则隔离。
- 初始焦点落在当前可用的主动作。打开 / 关闭 / 切换按现有输入中性释放合同处理，验证持有 A/B 时出现卡片的误激活风险。
- 终态返回完成导航前保留卡片反馈；导航或登录跳转失败保留明确错误和可重试动作。

### 5. 样式与布局

- 终态卡采用居中、单层面板，桌面目标宽度 480–560px，留出约 24–32px 内边距。标题约 22–24px，正文约 14–15px，主动作高度约 44px。
- 结构固定为状态图标与标题、短正文、帮助 / 当前阶段、动作行、可展开诊断详情。状态图标尺寸约 20–24px，颜色配合文字区分提醒与终止。
- 主动作沿用品牌强调色；返回使用中性样式；关机等有明确破坏性后果的动作使用危险样式。
- 复用当前浮层材质、主题变量与焦点效果，保证亮暗背景下文字清晰。四边留出完整焦点阴影安全区。
- 窄窗口动作换行，详情正文允许滚动，标题与主要动作保持可见；长错误码按词 / 字符换行，中英文长度分别检查。
- 简短淡入淡出与既有动效一致，尊重减少动态效果偏好。错误卡使用 dialog / alertdialog 语义与标题、正文关联；被动状态只在状态变化时温和播报。

### 6. 信息与诊断分层

玩家正文展示本地化状态和建议。技术详情默认折叠，包含发生时间、home / cloud、启动 / 首帧 / 播放阶段、错误码、自动恢复与补偿结果、清理状态和版本。

现场快照在 closeExecution 清空资源前捕获，并记录采样时间 / 有效性。详情与复制读取同一快照；快照中途缺样本时显示其可用性。复制成功使用“诊断信息已复制”，复制失败在当前区域提供重试。

详情中的 trace 关联信息按现有脱敏规则生成。诊断副本覆盖错误身份与安全字段；日志 / trace 继续保存既有排查证据。服务器地址、账号、主机 / 游戏标识、认证材料、SDP、ICE 和完整 URL 按当前规范处理。

串流健康诊断继续分列网络健康、恢复链健康、media supply、steady supply、submit / present 长尾与帧供给 delta。浏览器能力缺口与缺样本明确标记；错误卡根据已确认事实说明当前问题。

## 待确认与待验证

本轮按以下默认方向规划：

1. “央视”按“样式”理解，视觉沿用当前主题与浮层体系。
2. 本轮覆盖 main Browser 串流；共享 DTO 兼容 Rust 公共调用方，Native WIP 的专属细节由对应开发线承接。
3. 等待 / 恢复采用被动提示与主动查看问题；终态采用统一居中卡。首版继承当前触发期限。
4. 主机注册耗尽采用指引与返回列表；允许人工重试的前置条件在实施时与后端合同核对。
5. 认证恢复后的原目标续接，依据当前登录流程与路由能力评估；首版提供清理后重新登录与明确返回路径。
6. 播放后持续停滞提示覆盖、告警解除依据、重复出现规则，结合 runtime supervision 与 fresh trace 验证。
7. 场景预览使用演示数据，表达文案、布局与按钮后果；真实错误分类与状态仍需实施验证。

### 整体验收

1. 从任意错误入口进入相同场景，获得一致的标题、正文、动作和详情；home / cloud 的帮助与返回路径匹配。
2. 短暂观测失败与自动恢复沿用既有运行处理；真实远端终态、恢复耗尽和硬失败在当前预算内进入终态反馈。
3. 原始异常标识、栈与协议文本进入诊断层；玩家层仅展示明确的本地化内容。常见原因的说明均有证据来源。
4. 同一故障过程只有一张交互错误卡；新会话与旧错误隔离；终态接管菜单时焦点和 UI capture 正确收口。
5. 重试反复点击、重试中返回、清理超时、登录 / 导航失败、详情打开时新终态等组合均有确定结果。
6. 深浅主题、亮暗游戏背景、窗口化 / 全屏、窄窗口、中文 / 英文、键盘 / 手柄 / 鼠标完整验收。
7. 前端实现完成执行 `pnpm lint:fix`、类型检查与相关测试；Rust 改动执行 `cargo fmt` 与相关 crate 检查。实机故障样本记录提示时间线、恢复 / 清理效果和上述六类健康证据。
