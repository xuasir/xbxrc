# 云游戏菜单性能优化方案

日期：2026-11-12。状态：方案已形成，实施作为后续任务推进。范围：桌面 main 的云游戏目录、详情、页面切换以及相关缓存交付。

## 问题定义

用户实机反馈覆盖三个操作：进入云游戏到加载完成之前、详情页回退、切到其他菜单。优化目标是让目录更新期间的应用输入、页面切换和浏览保持稳定响应，并让成本随当前可见内容变化。

推荐按“页面生命周期与重复查询 → 渲染和计算规模 → 数据交付和持久化 → 图片与绘制成本”推进。当前源码已有目录缓存与渐进资料加载；本次查证还确认了失活详情实例重复查询、目录反复整体替换和卡片挂载规模持续增长。

## 当前约束

- 保持 Tauri + Vue 3 + TypeScript + Rust；接口、认证、缓存策略与持久化继续由现有 Rust data 服务负责，Vue 持有供 UI 消费的轻量投影。
- 复用几何寻路、焦点域、section + product 稳定节点以及详情回退合同；虚拟列表向现有引擎提供已挂载的候选节点与按需挂载能力。
- 保留公开浏览、账户准入、allowed / denied / unknown 权益、目录暂缺收藏、官方栏目顺序、来源失败降级和 scoped 刷新终态。
- 沿用账户、区域、市场、语言的目录 scopeKey；认证代次、语言变化和账户切换负责失效及迟到结果隔离。
- 当前商品资料按条目 24 小时补新、7 天降级展示；账户 overlay 新鲜期 10 分钟、可展示期 24 小时；详情新鲜期 24 小时、失败降级 7 天；排队预估沿用稳定聚焦 500ms、60 秒缓存和最多两路查询。
- `RemoteImage` 已使用 `loading="lazy"`、`decoding="async"` 和 Tile → Poster 回退；图片网络缓存由 WebView 承接，尺寸与解码驻留预算需要补齐。
- 2026-11-11 云目录交互增强已完成自动功能验证，实机验收仍在后续验证范围；云授权兼容任务和 UI 动效实机验收继续独立跟踪。
- 公共 catalog flow 同时服务桌面与 iOS；共享字段的扩展保持兼容默认值。运行时与状态架构调整先进入实施 RFC。

历史依据：[云目录实施 RFC](../rfcs/2026-11-11-cloud-catalog-ux-implementation.md)、[Report](../reports/2026-11-11-cloud-catalog-ux-implementation.md)、[几何导航合同](../../dev-docs/gamepad-navigation.md)、[UI 动效 RFC](../rfcs/2026-11-10-ui-motion-vitality.md)。

## 方案选择

| 方向 | 收益 | 成本与适用范围 |
| --- | --- | --- |
| 扩展缓存命中与预热 | 降低资料接口等待与冷启动重复请求 | 现有缓存已覆盖主要资料；收益主要集中于网络和读盘，生命周期与 DOM 规模继续需要处理 |
| 生命周期隔离、共享目录投影、按 revision 更新 | 直接压低回退和切菜单时的查询、整表派生和隐藏页面工作 | 生命周期修复可先交付；共享投影及事件合同进入复杂任务 RFC |
| 可见窗口渲染与图片预算 | 让卡片、焦点候选和绘制成本受视口约束，改善持续浏览 | 需要联动焦点恢复、LT/RT 跳栏、列数变化及图片生命周期 |

选择后两项作为主线，缓存调整围绕测得的重复传输、持久化和图片成本实施。

## 推荐方向

### 阶段 0：建立三个操作的性能基线

同一台设备、相同 production 构建与固定目录分布，分别测缓存命中、缓存过期、首次加载。记录从输入到页面激活、缓存内容可交互、每次目录提交和全量完成的时间。

- WebView：输入处理、Vue 提交、长任务、帧间隔、DOM/卡片/候选数、目录派生耗时、图片请求及原始/解码尺寸。使用采样计数和聚合窗口控制观测开销；WebKit 的采样通过实际可用的时间线、帧间隔和显式性能标记完成。
- Rust：每个 scope 的查询/刷新次数、序列化字节与耗时、快照克隆/合并耗时、`store.save` 次数/耗时和共享锁等待。
- 内存：应用及 WebView 进程占用、活动详情实例数、目录订阅数、图片数量；重复往返后观察驻留是否进入稳定区间。

沿用既有 trace 的聚合输出规则，诊断记录使用计数与匿名代次。基线应覆盖 500、2,000、10,000 条数据，以及真实分布的最近 25 项、新入库/热门约 30 项、离库约 14 项和大量收藏。此前 2,000 条功能 fixture 的每条官方横栏仅 4 项，其结果主要证明交互行为。

### 阶段 1 / P0：修复失活页面请求与重复热返回

1. 云详情保存所属路由/商品快照，查询入口校验活动状态和有效商品 ID。失活时撤销页面订阅、排队预估、页面定时器，并使页面请求代次失效；迟到结果只更新现有共享缓存中仍有效的范围。
2. 云详情采用一个组件实例承接当前商品，详情数据按 product + market + language 缓存，最近浏览状态有界保留，建议起始容量 30 项。针对云详情收紧实例复用，其他页面沿用各自当前缓存合同。
3. XCloud 回退时立即复用已接受目录、搜索、滚动位置和商品/操作锚点；当前范围和时效通过现有数据权威校验。范围失效、显式刷新和已到期数据触发新查询。首次 mounted/activated、auth 事件和手动刷新统一在途去重。
4. 失活 XCloud 暂停目录的视图提交与派生，只保存最新 revision/待应用状态；重新激活应用当前范围的最新一次结果。Rust 共享刷新可完成缓存填充，其生命周期由既有 owner 管理。
5. 初始目录结果、认证状态、偏好加载独立推进；先提交可浏览内容与可用操作，再补账户/偏好投影，保持收藏冷读、范围隔离和启动资格核验。

完成门槛：上述四步回放在回退与设置阶段的详情请求、全目录查询均为 0；打开 B 时仅活动详情发起所需单商品查询；有效目录范围的热返回保持目录传输次数为 0。生命周期断言覆盖真实 Vue hooks。

### 阶段 2 / P1：有界渲染与一次性索引

1. “所有游戏”按行虚拟化，挂载可见行、前后各两行预取和当前焦点行；横栏使用水平窗口，页面垂直方向只挂载可见及邻近栏目卡片，栏目标题和占位高度保持稳定。
2. 将网格和横栏的挂载预算统一到视口，1280×720 起始目标为总卡片数 ≤120、活动焦点候选 ≤400；长列表仍保持完整索引和可到达性。布局密度、列数及窗口尺寸决定实际窗口。
3. 焦点记忆保存 section + product + action、行内相对偏移与筛选上下文。跨窗口移动、LT/RT 跳栏、返回详情时，先挂载目标窗口，再由既有几何引擎定位；焦点卡片及其播放/收藏兄弟入口在操作期间持续保留。
4. 目录使用 `shallowRef` 承接不可变投影；建立 `byProductId`、目录成员 Set、收藏/置顶 Set、栏目排序 ID 与预归一化搜索字段。按内容 revision 或变更商品更新索引，空搜索直接复用当前排序结果。
5. 搜索输入立即显示，搜索计算采用约 120ms 合并和请求代次保护；较大数据按时间片派生。名称优先、别名、多词 AND、分类和 description 搜索合同延续。后台资料尚在补全时保留明确的结果时效状态。
6. 卡片采用稳定 view model，图片候选数组与标签随商品变更生成；等待时间和选中/启动状态只影响相关卡片。列表成员判断改为 Set/Map 查找。
7. 导航继续以几何距离选择候选，在活动页面与最上层弹层内缓存候选及单轮祖先可见性/矩形；结构和可用性变化负责失效，封面状态及焦点环视觉样式更新使用更窄的通知。滚动时合并布局读取与焦点环刷新到每帧一次。

完成门槛：浏览至第 2,000 项后，卡片和候选数保持预算；搜索清空、刷新排序、缩放和详情回退都恢复商品锚点；三个卡片入口、鼠标/触屏/手柄导航可到达性通过。

### 阶段 3 / P2：减少整份目录交付和重复保存

1. Rust 保持目录事实与时效权威，Vue 共享一份 UI 投影。初次进入或 scope 变化取得快照；详情从共享投影按 ID 读取摘要，直接深链通过单商品缓存/公开资料查询补齐。
2. typed RPC/event 增加独立 `contentRevision`；来源状态、refreshing、错误终态使用轻量状态更新。内容更新按商品合并或 scoped patch 交付，保留栏目顺序与删除事实；revision 缺口触发一次去重快照同步。
3. 完成事件和手动 RPC 响应对同 revision 幂等；后台批次按约 250ms 聚合、单批起始上限 75 项，刷新终态即时交付。失活页面复用共享投影，重新激活提交一次最新视图。
4. 商品补齐优先当前首屏、最近/收藏和邻近窗口，剩余目录按现有有界查询预算低优先级补齐。完整描述、截图、语言等详情沿用单商品按需查询；现有商品 TTL 与权益校验继续生效。
5. 现有 cache repository 将单次目录阶段的 base/overlay/status 写入合并为一次保存，序列化与持久化在 Rust 的有界串行任务中完成；内存可用状态与磁盘保存状态明确记录。持久化建议 500–1,000ms 合并窗，终态和退出遵循有界 flush 合同。
6. 内存缓存按 scope/商品设容量与回收策略；失效和 LRU 在既有 owner 内实现。共享 `settings.xbx.json` 保存耗时测量结果用于判断是否需要后续存储隔离 RFC。

完成门槛：普通热回退全目录 IPC 为 0；同 revision 视图派生为 0；一次成功完整刷新显式保存目标 ≤2 次；后台刷新完整性、局部失败、合法空目录和断电/退出持久化语义通过验证。

### 阶段 4 / P2：图片与绘制预算

- 按卡片 CSS 尺寸 × DPR 选择已确认支持缩放参数的官方图片尺寸，卡片使用缩略图，Hero 和截图使用各自档位；其他来源沿用原 URL。
- 保留 WebView 图片缓存与现有候选回退，按视窗约束请求和解码驻留，设置适度预取并观察重复解码。冷首屏、热返回和图片失败分别测量。
- 用绘制采样核对卡片两枚图标的 `backdrop-filter: blur(12px)`、阴影、`:has` 与焦点动效成本。批量卡片图标优先实色半透明底，动效限定当前交互卡片；变更以实测耗时和视觉验证为依据。

### 验收指标

以下为首轮实施目标，基线报告同时给出原始值、改后值与测试设备。网络资料完成时间单独统计。

| 指标 | 目标 |
| --- | --- |
| 加载期间输入处理 | P95 ≤50ms；云目录相关单次主线程任务 ≤50ms；≥100ms 阻塞任务为 0 |
| 热回退/切菜单可操作 | P95 ≤300ms，包含现有页面动效；目录读取与重新派生带来的额外阻塞为 0 |
| 有效缓存内容可操作 | 本地缓存可用后 P95 ≤300ms；首屏优先展示，后台补全保持响应 |
| 失活详情请求 | 回退和切其他菜单时为 0；空商品请求为 0 |
| 同 scope/revision 的目录重复提交 | 全目录 IPC、索引重建和内容视图提交为 0；状态终态单独更新 |
| 挂载规模 | 1280×720 总卡片 ≤120、焦点候选 ≤400；目录从 2,000 增到 10,000 后保持视口规模 |
| 导航 | 全部商品可到达；保留唯一焦点和主体/播放/收藏入口；局部几何选择 P95 ≤8ms |
| 内存与生命周期 | 至少 20 次目录/详情/其他菜单往返后，详情实例、订阅和进程驻留进入稳定区间；云详情活动实例 ≤1 |
| 数据可靠性 | 账户/语言/区域切换、超时、旧结果、合法空目录、暂缺收藏、缓存过期及刷新终态回归通过 |

自动验证使用 production 构建与真实 Vue 回放，模拟目录覆盖规模和失败组合；Tauri 原生窗口、物理手柄、低功耗和实际网络环境由用户实机验收。检查范围包含适用 Vue/Rust 回归、导航覆盖、lint:fix/typecheck/build、Rust fmt/check 与 trace 生产预算。

## 待补证据

1. 实机在三个操作中的 JS/布局、图片解码/合成、Rust 持久化与锁等待占比，以阶段 0 的同设备对照报告锁定。
2. 实际目录数量、收藏量、封面尺寸、WebView 进程内存及官方图片缩放参数支持情况，以匿名计数和尺寸采样确认。
3. 保持当前 220/280ms 动效时的“可操作”时间与输入合同，通过实机和自动回放定义相同的测量起止点。

这些数据用于调整窗口和批次预算，生命周期请求隔离已经具备直接实施依据。
