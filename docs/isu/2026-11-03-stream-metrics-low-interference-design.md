# 串流指标低干扰展示方案

## 问题定义

运行指标帮助玩家判断画质、流畅度和网络情况；诊断指标帮助定位网络、解码、显示和恢复问题。本次设计把两类信息按使用频率分层，优先留出游戏画面。

当前 `main` 的体验面板包含 12 个指标，浏览器诊断面板包含 45 行。体验面板位于右上角，诊断面板固定从 `top: 132px` 开始；体验面板展开后，两者会争用同一片区域。诊断面板还常驻 GPU 耗时、实际上屏等固定“不可用”项，以及画像、动作效果和长决策摘要。

用户已确定：第二类面板统一命名为“诊断指标”，开启后直接使用分组详情模式。

本次产出为设计方案与交互预览，开发执行由后续 `task-run` 任务承接。

## 当前约束与依据

- 延续 [2026-05-12 信息架构拆分 RFC](../rfcs/2026-05-12-stream-panel-information-architecture-split.md)：运行指标使用共享体验语义；诊断指标按 runtime 能力提供专属内容。
- 本轮针对 `main` 的 Browser 运行线路。Vue 3 + TypeScript 负责显示投影；现有统计、恢复策略与 Rust 公共合同继续承担原职责。
- [面板可靠性任务](../project-task.md) 已确立实时源分辨率、视频码率、最近 5 秒丢包窗口，以及接收、解码、呈现观察帧率的独立口径。
- `StatsService` 的 `presentFps` 在 Video 路径来自视频推进观测，在 WebGL 路径来自渲染提交观测；浏览器实际屏幕 scanout 与 GPU 耗时当前能力不可用。
- 页面读取同一份 `performanceSnapshot`，当前面板刷新周期为 2 秒，底层浏览器采样由现有共享采样器提供。
- 指标开关当前默认关闭，离开会话时复位。手柄交互沿用 geometric navigation 与串流输入路由。

## 方案比较

| 方案 | 展示结构 | 主要取舍 |
| --- | --- | --- |
| 紧凑双面板 | 缩短现有体验卡片与诊断卡片 | 实现量小；两块浮层持续占用画面，宽高仍随字段变化 |
| 顶部运行条 + 诊断详情 | 5 项运行指标；诊断开关直接打开分组详情侧栏 | 游戏中可持续观察，诊断按需开启；交互只有开关、切组和关闭 |
| 全部放进诊断侧栏 | 菜单打开后查看全部指标 | 常规画面占用最少；持续观察运行变化需要保持侧栏打开 |

推荐“顶部运行条 + 诊断详情”。

## 推荐设计

### 顶部运行条

桌面示例：

`1080p · 59.8 FPS · 12.6 Mbps · RTT 26 ms · 丢包 0.0%`

| 常驻项 | 使用意义 | 口径与格式 |
| --- | --- | --- |
| 源分辨率 | 判断当前视频清晰度与远端降档 | 实时源尺寸；标准尺寸显示 `720p / 1080p / 1440p`，特殊尺寸显示 `宽×高` |
| FPS | 判断当前呈现观察帧率 | 采用现有 `presentFps`；显示 1 位小数；入口说明标明 Video / WebGL 的观测来源 |
| 视频码率 | 判断当前画质投入 | 实际视频下行，统一为 `Mbps`、1 位小数；有效 0 值显示 `0.0` |
| RTT | 判断网络往返 | 显示整数毫秒；字段标题保留 RTT，详情解释网络往返口径 |
| 丢包 | 判断近期网络损伤 | 最近 5 秒窗口百分比，显示 1 位小数；窗口与精确值在详情保留 |

信息迁移：

- 接收 FPS、解码 FPS 进入诊断指标的显示分组，与视频推进、渲染提交组成帧链。
- 抖动、总下行进入网络详情。
- 连接耗时、首帧耗时进入会话详情，以固定里程碑耗时展示。
- 状态、恢复与画面供给提示合并为一条条件状态；正常播放时仅展示数值。
- 中继、服务器、策略画像、超分实现进入对应诊断详情。中继属于路径属性，按普通信息展示。

视觉与布局：

- 顶部居中，距可用内容上边缘 12–16px；内容宽度自适应，桌面目标约 480–560px，高 30–32px。
- 单行、小圆角、白色主数值、低强调标签与分隔符；底色采用约 24% 黑色透明度，轻文字阴影保障亮画面可读性。
- 使用 12px 左右字体与等宽数字，给数值预留稳定宽度。正常数值使用统一中性色，异常字段与短状态使用强调色。
- 运行条处于被动显示层，点击穿透；开关与口径说明放在现有诊断菜单。
- 宽度充足时显示 5 项；空间紧张时优先保留 FPS、RTT、丢包，分辨率和码率收进详情。恢复状态可优先占用码率槽位；窄窗口恢复时优先显示状态、FPS 与 RTT，让条高保持稳定。
- 顶部位置结合标题栏安全区和菜单按钮避让；全屏按同一结构展示。

状态与更新：

- “画面恢复中”“画面暂时停滞”等短文案来自既有诊断事实；单次只展示最高优先级状态。优先级为当前无画面、显示供给受限、恢复中。
- 指标开关沿用当前默认关闭行为；用户开启后，运行条持续显示，菜单自动隐藏独立处理。
- 初次采样用“采集中”与必要空位表达；过期快照标记“数据暂缺”，让数值可靠性显式可见。
- 先沿用当前 2 秒刷新与统计窗口；字段格式化收敛精度，状态使用现有响应通道。刷新速度调整可作为独立任务评估。

### 诊断指标：直接使用详情模式

现有诊断菜单提供“诊断指标”开关。开启后直接打开右侧约 340–380px 的分组详情侧栏，标题统一为“诊断指标”，按网络、显示、恢复、会话四组查看。

交互路径固定为“开启 → 查看与切组 → 关闭”。关闭按钮或 Back / Escape 关闭诊断指标并恢复串流输入；再次开启时沿用当前会话的分组选择。运行条与诊断指标独立开关，诊断详情打开期间运行条继续显示。

面板使用 12px 左右文字、单层底色与细分隔线；各组保持固定字段顺序，样本更新只更新值。窄窗口采用适配宽度，标题、切组和关闭操作均保持可见。

| 详情组 | 保留内容 |
| --- | --- |
| 网络 | RTT / 基线 / 增量、网络抖动、5 秒丢包、视频 / 总下行、请求 / 协商码率上限、路径与控制通道 |
| 显示 | 帧链、回调交付、CPU draw / upload / GL submit、提交距今、源 / 输出尺寸、渲染管线、实际 SR 状态、渲染动作效果 |
| 恢复 | 呈现阶段、恢复归因、最近恢复效果、关键帧请求结果；能力与样本有效性一并说明 |
| 会话 | 连接 / 首帧耗时、传输与中继路径、采样时间 / 窗口 / 观测状态、画像预设与完整决策文本 |

固定不可用字段从指标列表移出；相关组末尾用一条能力说明解释浏览器可观测范围。`覆盖 / 限流 / 失败 / 截图绘制`等累计计数放在高级详情，使用完整标签和单位。超分以实际运行态为主，配置目标与回退原因放在显示详情。

首次打开详情建议优先进入与当前异常归因相关的组；用户选择后，组选择保持稳定。完整技术字段在详情、快照与 trace 中保留，展示精简通过投影完成。

### 输入与可访问性

- 运行条保持被动观察；开启诊断指标或操作菜单时沿用现有 UI 输入捕获合同。
- 诊断开关、分组与关闭按钮接入既有 FocusScope / geometric navigation；关闭后恢复串流焦点与输入归属。
- 鼠标、键盘和手柄都可完成开关、切组与关闭；操作目标约 44px，显示文字保持紧凑。
- 状态使用文字配合颜色表达；统计更新保持安静，状态变化使用适度辅助播报。
- 复制诊断快照作为显式操作，复用当前采样快照与现有脱敏规范。

### 实施与验收范围

优先修改现有体验组件、诊断组件与对应 view model / formatter，复用当前开关、enhancement 挂载与共享快照。旧 `performance_style` 的展示差异随统一运行条收敛，配置兼容策略在执行任务中明确。

验收重点：

1. 运行条在桌面保持单行；诊断详情与运行条、菜单、麦克风状态各有稳定区域。
2. 亮画面、暗画面、窗口化、全屏与窄窗口均能清晰读取；字段更新保持几何位置稳定。
3. 源分辨率、视频码率、FPS、丢包与当前 trace 同源；有效零值、缺样本、过期样本均有正确表达。
4. 恢复中、显示供给受限与无画面各自只出现一次状态表达；恢复结束后回到常规数值。
5. 诊断开关直接打开分组详情；打开、切组和关闭按现有输入路由验收，关闭后回到串流输入。
6. 面板复用同一采样结果；精简展示保留 trace 的诊断证据与既有采样预算。

## 待确认与待验证

这些事项按以下默认方向准备后续实现：

- 运行条位置采用顶部居中；亮背景下验证约 24% 底色是否充足，必要时提高到约 32%。
- FPS 采用现有呈现观察口径，在诊断入口提供来源解释；实际 scanout 能力随着平台统计演进。
- 诊断指标默认关闭，开启后直接进入详情；分组选择只在当前会话内保留。
- 诊断性能耗时暂用既有平均值；P95、供给 delta 等高级统计依据当前 runtime 的真实能力进入详情或 trace 报告。
- 异常颜色优先复用既有状态与阈值，新的平滑和告警阈值由独立证据决定。
