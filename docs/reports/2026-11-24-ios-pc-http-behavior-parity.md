# iOS 接口与错误行为对齐 PC（P0–P2）实施报告

代码改造和自动验证已完成，实机验收待用户。依据 [RFC](../rfcs/2026-11-24-ios-pc-http-behavior-parity.md) 的既有实施授权，主窗口单独执行，沿用当前 SwiftUI、UniFFI 和公共 Rust 的职责边界。

## 交付

- **P0**：主机远程游玩不可用、尚未注册保持独立提示与重试动作；Query 保留 DNS/connect/TLS/body/timeout、安全服务码和协议码。UI 和 trace 使用同一类型化错误事实。
- **P1**：主机查询沿公共预算；合法空列表与无效响应分别处理。Cloud 等待、目录、来源和官方触屏资源提交被拒目标 token，由对应 Rust 凭据 owner 恢复一次；Swift 接收最终结果。
- **P2**：失败后经过 15 秒冷却可重新激活，取消后释放初刷标记，成功内容继续显示。详情按产品、市场、语言持久缓存，24 小时新鲜、7 天 stale，30 槽、两路并发；同键合并，最后一个等待者取消时终止底层读取。
- **取消与下载**：UniFFI 生成修补覆盖可抛错 future 的取消与一次释放，清理入口完成原有 teardown。相册每次下载前续址，保留 HTTP 状态及 Retry-After，区分过期、权限、限流、服务失败、网络、空文件、大小和格式；校验成功后发布导出文件，失败与取消清理临时文件。

## 边界与后续验收

- 下载资源总期限为 300 秒、最大 2 GiB。原生 URLSession 公开配置与 PC 的连接专用 5 秒预算存在平台差异；等待配置采用 300 秒，避免对整个媒体读取施加 5 秒空闲截断。
- 自动测试采用无凭据本地夹具。真实 Cloud 401、签名媒体服务响应、主机等待/再次连接以及手机串流长测由用户手动验收，登录现场根因仍需运行证据。
- 公开商品资料按市场和语言缓存。访问 token、认证结果与签名下载地址继续由既有 owner 管理。
- 续接期间三个其他任务文件发生变化，已记录并保留；原暂存区 SHA-256 与续接基线一致。

证据与本轮独立差异见 [验收目录](../../dev-docs/validation/2026-11-24-ios-pc-http-behavior-parity/README.md)。本轮临时目录、构建与 xcresult 清理结果见同目录 `cleanup.json`；共享 Rust/WebRTC 缓存继续保留。接下来在手机上验证主机再次连接、Cloud 凭据拒绝恢复和相册下载。
