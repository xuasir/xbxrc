# SR、锐化与默认渲染控制改造报告

## Summary

关联 [RFC](../rfcs/2026-11-09-render-controls-clarity.md)。SR、锐化和默认渲染的控制、配置范围及实际状态已经统一，工程实现、自动验证和组件预览完成。实机持续帧率与增强回退继续由掌机日志验收。

## Delivered

- Video 的普通界面名称为“默认渲染”；锐化采用“关闭 / 清晰 / 柔和”，SR 与独立锐化互斥。
- 设置页保存全局默认。串流页“应用本次”只更新本次会话，“保存为默认并应用”显式更新全局，“恢复默认”恢复本次持有的默认配置。
- 可开关顶部指标栏显示已提交模式及短回退原因，如“默认渲染 · 帧率保护 / 设备限制 / 增强失败”。准备和切换状态随既有资源事件更新。

## Changes

### 配置和显示意图

Rust 配置以 `render_mode = video | sharpen | sr` 为权威，旧 SR 布尔和锐度按原始键迁移。清晰使用锐度 3（60%），柔和使用锐度 1（20%）；关闭保留记忆参数，默认渲染和 SR 的独立锐化执行值为 0。标准、鲜明、柔和色彩风格独立调整颜色。

两个页面共用 SettingDisplayOptionsSheet。会话内按预览、A/B 临时覆盖、本次已应用配置、启动默认快照的顺序投影。取消恢复已应用配置，重试和重连保留本次调整；异步保存和临时恢复绑定执行及调整代际。启动等待结束后读取最新配置，首次装配也包含等待期间的操作。

### 实际管线和回退

PlaybackService 的已提交资源提供实际管线、锐度、代际和回退原因；Browser runtime 通过既有事件通道向页面更新并去重。顶部状态独立于诊断轮询。候选准备期间保留已提交模式并显示切换状态。

SR 和独立 WebGL 增强的硬失败直接回到 Video。默认渲染采用原视频与 CSS 色彩，已移除该路径的 SVG 锐化，并将色彩选择器绑定到实际视频节点。主动选择默认渲染会清除旧技术回退标记。

SR A/B 通过完整临时配置覆盖执行，结束后恢复模式、力度、颜色和来源；目标 renderer 交接等待上限为 6 秒，截图标签读取实际状态。目标回退或超时显示明确的模式不可用错误。

### 控件导航和布局

实际窄屏预览复现了固定底部按钮抢占纵向焦点，以及 Scope 注册前提前聚焦关闭按钮。修正后，纵向移动先使用当前滚动区内的几何候选，到达边界后进入区外操作；横向移动保留原几何候选。Scope 的 DOM 准入随注册一起开放，默认焦点准确落到 SR。

顶部指标栏采用内容宽度和视口上限，1280px 场景单行高 32px，360px 场景两行高约 42px。窄屏提交栏将保存默认放到独立一行，取消和本次应用共享下一行，保留可滚动内容空间。

## Risks

- 锐化和 SR 的持续性能存在已观察到的设备差异；[最新实机分析](../../dev-docs/validation/2026-11-09-sr-sharpen-fresh-trace-analysis.md)继续作为性能调查依据。
- Windows 掌机的实际触屏、物理手柄、自动回退、重新连接以及长测由用户执行；当前验证提供工程和组件层证据。

## Follow-up

保持 1440p/60fps，依次验证默认渲染、锐化柔和、锐化清晰、SR，并检查顶部实际模式。普通本次应用后核对全局默认；显式保存后开始新串流核对默认。后续 trace 按网络、恢复链、media / steady supply、提交长尾和帧供给 delta 继续检查持续掉帧。
