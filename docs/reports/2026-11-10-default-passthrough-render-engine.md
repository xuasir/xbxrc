# 默认逐帧直通与可组合画面处理交付

日期：2026-11-10；关联 [RFC](../rfcs/2026-11-10-default-passthrough-render-engine.md)。代码实施与局部检查完成，任务状态为 Validation Pending，ROG 与其他 Windows 设备由用户实机验收。

## 交付行为

- 默认原画、SR、锐化与风格使用同一逐帧 WebGL 引擎，效果切换原地更新处理计划。SR 关闭时跳过重建，锐化关闭和标准风格跳过对应计算，全部关闭时直接采样显示原画。
- SR、锐化关闭/柔和/清晰、风格独立配置，界面显示“原画”或效果组合。用户通过“渲染降级”处理异常，原设置保留，降级期间全部后处理暂停；关闭降级后恢复配置。
- 缺少 WebGL2 或遇到 shader、纹理、context、首帧硬故障时保留基础视频呈现与原因。主动重试沿首帧交接恢复，重复操作复用候选，旧画面保持至新候选成功。
- 持续帧率压力产生诊断建议；兼容设置和明确故障决定引擎切换。逐帧接口缺失、初始化/首帧超时或读取失败时，通过既有 renderer 故障通道直接切到 video 标签呈现，保留具体原因与配置。

## 实现与合同

Rust 与前端统一使用 `render_compatibility_mode`、独立 SR 开关及画面参数。新默认降级关闭、SR 关闭、锐化 0、标准颜色；旧 `render_mode` 仅参与配置迁移，保留原有效效果和颜色。全局默认、本次应用、预览取消与重连继续沿原范围执行。

现有 SR renderer 收敛为统一引擎的兼容入口，EASU 重建按需装配。SR 原固定 RCAS 与其他锐化合并为用户控制的一次 USM/CAS；SR 单独开启时执行重建，共享锐化由独立开关决定。旧融合 SR 路径已退出当前装配，重建与最终处理采用两次 GPU pass。截图继续复用当前帧，A/B 仅翻转 SR 并保留锐化、风格与范围。

实际状态读取已提交引擎及资源，SR 是否实际重建由源/目标尺寸决定；日志报告实际公共锐化路径，RCAS 基础值保留为旧配置口径。恢复按钮使用“重试画面处理”，渲染方式保留在诊断合同中。

默认 WebGL 仅上传独立 VideoFrame，初始化阶段等待解码供给；RVFC / 播放计数保持呈现诊断。暂停截图复用最后解码帧的已上传纹理，供给失败后的重试重新建立 reader 并沿首帧交接恢复。接续启动期限与严格降级修正见[修复报告](2026-11-10-decoded-frame-startup-deadline-fix.md)。

## 实机验收范围

本轮证据确认配置、处理计划、供给调度和资源合同。ROG 原画帧率、SR 新装配的观感与 GPU 成本，以及其他 Windows WebView2/驱动的能力与回退需要新版本实机验收。原 ROG 反馈沿体感对照保留，量化结论需要同时查看网络、恢复链、media supply、steady supply、submit/present 长尾和帧供给 delta。

建议先在 ROG 使用默认原画，再启用 SR、锐化与风格组合；渲染降级用于画面异常时的对照和恢复。
